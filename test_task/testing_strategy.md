# Стратегия тестирования

1. Протестировать сайт [Signaturely](https://staging.d2twwklgqmrfet.amplifyapp.com/login) - сервис для электронной подписи документов. На сайте можно подписывать документ самому или отправлять другим. Существует 3 плана, в зависимости от которого расширяется функционал сервиса: можно подписывать еще больше документов, добавлять шаблоны или создавать команду.
2. Пользовательское исследование сайта.
3. Написание тест-кейсов и чек-листов, используя типы и методы тестирования, описанные ниже.
4. Функциональное тестирование. Проверка работы каждого блока программы в отдельности и их взаимодействие между собой. Проверка функциональностей программного продукта при стандартном его использовании. Проверка работы продукта при нестандартном его использовании путем ввода или загрузки некорректных данных или файлов.  Цель - обеспечить максимально возможное покрытие тестами программного продукта.
5. Нефункциональное тестирование:
  - проверка сайта на кроссбраузерность (во всех браузерах сайт выглядит одинаково, текст читаемый, функционал не ограничен);
  - проверка сайта на кроссплатформенность (на разных устройствах в DevTools);
  - проверка адаптивности верстки сайта (страница подстраивается под разное разрешение);
  - тестирование производительности (проверка оптимизации работы сайта при разной скорости интернета);
  - частичная проверка безопасности сайта (проверка всех полей ввода на уязвимости путем ввода JS скрипта и HTML кода);
  - проверка UI/UX
6. Использовать техники тест-дизайна: 
  - метод декомпозиции;
  - классы эквивалентности и анализ граничных значений для форм ввода;
  - классы эквивалентности для файлов загрузки;
  - диаграмма состояний и переходов для каждого блока;
  - техника pairwise в программе “Pairwise Pict Online” для фильтров.
7. Проведение тестирования по написанной документации.
8. На найденные дефекты завести баг-репорты и проследить их исправление.
9. После исправления всех дефектов, провести регрессионное тестирование всего функционала.
10. Написание и проведение негативных тестовых сценариев.
11. Нетестируемые компоненты: страница Feedback.
12. Критерии приемки - определить и утвердить условия и критерии, которые должны быть выполнены для успешного завершения тестирования и приемки продукта.
13. Составить отчет о тестировании.
